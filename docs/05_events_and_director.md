# 72项随机事件与调度

> **V0.6 当前权威：**条件生产、期限、到场重检、提前处理与终态以 [condition_lifecycle_v06.json](../content/condition_lifecycle_v06.json) 和 [条件自洽修订](23_condition_consistency_v06.md) 为准。当前事件变体仍见 [60怪派生](21_monster_gameplay_v05.md) 与 encounters_v05.json，events.json 保留历史/当前反向引用。事件 choices 表示场内可执行策略，不要求弹选择题。普通主工作只影响评级；重大事件中守住边界/处理主怪仍属安全要求。

> **历史目录：**[V0.4交互卡](12_all_encounters_v04.md)、[V0.4共享系统与导演](14_systems_and_director_v04.md) 及下文标明的 V0.3 记录仅保留为历史参考，不能覆盖当前条件合同、怪物卡或地图补件。

事件数量扩展到72项，分8组各9项。它们包括工作、天气、身份、群体、白天与正向事件。所有后果都是本作设计，不是对民俗事实的断言。

## 当前事件怎样改变操作

当前60怪各有两项事件变体，共120项，写在encounters_v05.json。变体必须改变可见对象、路线、状态或窗口，并给出具体应对；不能只写“SAN多扣一点”。同一物件不允许同时要求开与关、湿与干，除非给出可分时步骤或独立绑定。

特殊订单替换当小时两个基础名额，不额外增加第13笔；继承原名额的窗口领取/真实入店要求。百鬼夜行的两笔特殊交易也遵循此规则。怪物工作与普通工单共享同一实物动作时只记一次，但不重复扣两次时间。开门、纸号交付、退让、封袋等是世界操作，不必把每个事件变成选项框。

随机事件不是用来临时取消唯一基础解：F13登记冰柜必须可用；F12诱离出口不得被队列堵住；河童水路与雨水分来源；F60唯一转身提示不会被黑视完全盖住。

普通定时主怪通常在阶段预算钟第20秒到场；F26、F32等响应型先等待真实条件成立，再检查剩余时间和席位，使用自己的世界时钟预告。F32至少需要45秒当前阶段预算与45秒有效血源剩余寿命，才启动12世界秒预告；不能为了抽到吸血鬼而直接让同事受伤。预兆后提前包扎、隔离或完成工作可记提前防范，不重新造伤、补造货物或立即补刷主怪。

## 历史 V0.3 动作变体说明

本节记录旧版12项动作变体的设计背景；当前每次动作最多两项操作负担（包括SAN）、条件来源及准入顺序，均以V0.6条件合同与当前怪物卡为准。

夜间表格的“选择”现在表示玩家采取的处置计划，不代表点选文字后任务自动完成。玩家仍须执行对应工作模板：取货、搬运、开关、清洁、扫码或部署，再由物件和工作状态产生结果。白天安排与签约确认仍适合菜单选择。

`content/event_variants.json`给出12项明确映射到E事件、W店务与F原型的动作变体。事件只修改已实现的锚点、通路、设备、可见性和操作参数，不重写怪物核心目标。F12始终通过玩家回形针诱导出店；F13始终通过指定生肉箱的合法入柜解除。两怪各另有3项针对性变体，见[追逐蓝图](11_encounters_v03.md)。

首轮同一时刻最多一个主动追逐者；每项工作最多叠加两种空间或操作限制，SAN另受统一精度与视野下限约束。实际投放还要确认所需功能已实现；图鉴中的候选或默认启用标记不表示该功能已经开发。F13与唯一冰柜失效、F12与唯一出口封死均禁止组合。

阶段容量按120秒工作预算处理：路径与世界动作消耗真实模拟时间，精细特写先锁定成本、退出时结算一次。QTE失败的一次补救成本也要预留；不足时减少可选交易或不投事件，不能取消既有承诺、自动完成店务或延长06:00。

每夜先以2—4项小事件、最多1项大型事件调参；白天0—2项。必需事件提前预留窗口，其他事件可以按当前压力减少。已经完成的正确处置不会被导演以免费残留形式复活。

## 时间字段与工作计入

`allowed_hours`为游戏时钟上的允许开始小时：夜间0—5；白天行动格为8、10、12、14、16、18；整备窗口为20。事件不得进入22:00—24:00的必要验岗。`latest_finish`使用`hour_end`、`action_slot_end`或`22:00`，分别表示当前夜间阶段末、当前2小时行动格末或当日整备结束。`duration_seconds`只记录夜间实际处理预算，包含行走、核验、操作与善后；白天按行动格结算所以为0，不能据此免费取得活动收益。每项选择的`time_cost`另列原有行动格或整备分钟。

夜间小事件通常占4—24秒处理预算，只有当“既有必需工作＋已承诺遭遇＋本事件有效操作＋移动与资源修正＋至少10秒余量”能放入剩余阶段时才派发。处理预算不等于效果寿命：读取已有规则和系统暂停冻结全部时钟，现场观察继续消耗世界时间，已开始精度特写的明示成本退出时只结算一次。特写不得跨过下一尚未派发的订单、预兆或阶段标记；同刻标记先派发再准入。天气、伤口和仓位若跨小时，必须保留真实剩余寿命并登记下一阶段负担，不能以切小时删除；延期也不消除已承诺任务。

`work_credit`区分额外工作、原有任务的替代步骤与通知修正。只有操作真实完成、对象匹配且形成验收记录时才能抵扣对应工作；同一动作不能重复领奖或抵扣无关任务。白天活动选择占用或替换现有一格，不能再叠加原计划的完整收益；不参加则保留原计划。采购折扣、退款和睡前噪声处理绑定既定采购、整备或睡眠活动，无隐形加时。

20:00—22:00共120游戏分钟，基本整备固定预留60分钟，可选处理共享剩余60分钟。公交绕行占用这60分钟弹性；维修、抽奖等可选处理若已无余量就延期或不提供，不能侵占22:00后的验岗。

## 联动与公平性

[synergies.json](../content/synergies.json) 保留18条历史记录，15条属于当前设计；S03、S11、S12已停用。当前设计不等于默认开启或客户端已实现，仍需逐条检查开关、条件与预算。奖励必须有明确生产来源、消费动作、次数和到期；没有实际消费者的保护令牌不能作为减难依据。

事件与原型通过标签关联，例如water、sound、threshold、identity、food、cold、path。标签只帮助检索候选，不自动证明两个机制相容。每个获准组合仍需明确因果与动作顺序。

总压力由活动实体、事件、环境、资源脆弱程度、人员缺位和条件联动组成。同事可可靠代班时，部分操作成本下降；同事待核时，原有低难任务也可能变成高负担。低精力和饱腹只通过真实动作耗时与体力恢复改变可行性，不能再重复加一遍隐藏惩罚。

派发先做硬约束：所需规则可查、必需工具可得、独立证据可得、安全路线可达、人员权限足够、动作与行走能在期限内完成且预留余量。最后才比较压力预算。预算不足可留空主槽或使用正向事件。任何组合的可行性只保证在派发当时存在合理策略，不保证之后任意误操作都能挽回。

规划、首次预兆、到场及实际提交动作时都要复核条件。真实订单、事故、工作痕迹和设备故障须先有可追溯来源；导演可预留条件型席位，但不能把预留当事实。伤者始终是主角或唯一同事原实例，F33来客外观伤痕不自动成为F32血源。F32的柜台员工边界使用明确 `marked` 状态且没有授予该怪员工区权限，不能把普通柜台当所有怪通用的安全点。

恐慌恢复不以跨店跑到固定点为前提：首次免费安定可在世界中步行进行，20秒期限内累计完成8秒安定，受击或工作会中断且保留进度；不暂停怪物、不提供物理免疫。组合准入须保留这项实际操作机会，不能把“理论上有安全柜台”当作已经证明可达。

首周活动实体上限按七夜为1、1、2、2、2、3、3；压力预算先用3、4、5、6、7、8、9。新增主遭遇通常每小时1个。大型事件占主位且占一个活动席位，其内部群众是统一流程；若使用独立攻击实体，必须另计席位和压力。第一周同一时刻最多一个假扮者。

E028—E036的异常版本必须绑定已经获准的F系列实例，`bound_entity_id`指向该运行时实例。人员事件不能通过“小事件”身份额外生成怪物；模板未绑定时只能展示正常迟到、重复线路或等待核实，不能出现第二具同事实体。F实例的席位与基础压力只算一次，人员事件只加尚未纳入该实例预算的实际额外工作。封签是可转交或盗取的物件流转证据，高风险身份权限仍需两个独立来源；详见人员系统。

## 跨夜契约预留

E071及其他产生跨夜履约义务的交易必须在确认签约前完成预约：固定到期夜、04:00—05:00清算小时、资源金额、退出条款和处理时长，显示给玩家后才发放收益。未签约前可以选另一个有容量的到期夜；签约后不随机改日，也不因导演压力高而跳过清算。

同夜兼容债务合并为一次E045，最多3份。清算预留40秒：核对清单8秒、各债务最多8秒共24秒、写回与退出8秒。40秒处理之外仍预留该小时实际关键工作、行走与至少10秒余量。履约动作不同或总耗时超出容量的合同不得塞入该批次；应在签约前另选有容量的夜晚或放弃新合同。

这次清算提前占用当夜唯一大型事件配额与04时主槽；百鬼夜行等随机大型事件不再在同夜抽取。多份合同只合并窗口，不合并或隐藏各自代价。签约后已预留的窗口、债务清单和退出成本写入存档；玩家后来主动花掉偿还资源时，执行原先明示的退出／违约流程，导演不能删债、临时追加惩罚或偷偷送资源。

## 随机与存档

真实06:00先结算本时刻到期的契约并释放合法预留，再检查关键危险并进入交班专用状态；不等待交班后才解除阻挡交班的契约。未结束的敌对威胁没有无限补时，普通未完工作不因交班获得额外奖金。次夜奖励绑定实际下一夜与可消费目标，不能靠跨周重建实例刷新次数。

种子、主遭遇抽样、事件计数、已承诺契约、角色真假状态和奖券计数分别保存。读档不得重新抽奖而保留收益。相同种子下，已公开的信息和结果保持一致。首次新机制优先单独或低压展示，后续才进入强联动模板。
