# V0.7第二轮自洽审计：条件必须真实、及时、可用并能结束

> **历史审计说明：**本文件保留对应轮次的问题与修正记录。当前累计合同以 [V0.8版本边界](00_revision_v08.md)、[第三轮自洽审计](26_third_consistency_audit_v08.md) 和结构化数据为准；文中的旧版本结果不是本轮验证数字。


2026-11-18。本轮在V0.6实际来源合同基础上继续复核，不把“文档写了前提”视为“游玩时能够满足”。确认并修正了角色到场过晚、短窗口路线不成立、报价晚接必然超时、供物种类不符、奖励没有消费者，以及并行动作重复提交等问题。

**结论：已把发现的设计缺口落实到当前60卡、72事件及相关数据，并为具体程序反例增加参考检查。当前仍没有完整微信客户端，不能据此宣称所有随机组合、动态追逐或手机体验已经无死局。**

## 1. 条件采用八项合同

| 项目 | 必须回答的问题 |
| --- | --- |
| 真实生产者 | 谁通过哪次实际动作、事件或有限入场载荷产生它？过去的记录不能由当前怪物补造。 |
| 具体对象 | 属于哪名员工、哪件物品、哪份订单、哪次事故？同名不代表同一实体。 |
| 产生时刻 | 首兆前必须有的历史，是否真的早于首兆？角色是否已实际到场并完成核验？ |
| 寿命与时钟 | 用世界秒、阶段预算还是白天行动格？从哪个实际事件开始，怎样暂停、到期？ |
| 可见反馈 | 玩家能在哪里观察、复查和判断？隐藏真值不能替玩家完成身份识别。 |
| 实际动作 | 地图距离、占手速度、取放、开关和已有承诺合计，能否放入当前窗口？ |
| 用途与结算 | 物资被哪个动作消费、奖励由谁领取、哪个对象防止重复结算？ |
| 消失与结束 | 玩家先处理、拒绝可选请求、来源自然到期或动作被打断后，怎样安全终止或恢复？ |

条件在候选、首兆、到场、动作提交与结束时分别复核。已出现预兆的危险被正确预防，记该波已防范，不立即补刷惩罚玩家。未满足前提的候选不能靠造伤、造单或造历史填满每小时配额。

## 2. 员工流血的完整闭环

这是游戏内有限伤情合同，不新增生命值、失血等级、感染或永久伤残系统。普通轻伤不能自动变成可召怪的血源。

| 环节 | 当前明确设计 |
| --- | --- |
| E003来源 | 真实已登记的破玻璃退货物，先显示碎片与3世界秒警告；警告后仍徒手危险处理或实际接触登记碎片危险格，才生成割伤。安全清扫、隔离或退出可预防。 |
| F21来源 | 已实际激活且占有主遭遇位的F21玻璃护罩故障，绑定真实工位；40世界秒警告结束时，人员仍实际在危险区且未完成避险，才产生事故。不能单独调用“事故”函数凭空造伤。 |
| 流血持续 | 实际割伤提交后90世界秒；系统暂停冻结，阶段切换不清除，精度特写只增加阶段成本时不代替世界流逝。 |
| 普通轻伤 | 30世界秒内体力恢复倍率0.85；不减普通走路速度、不自行掉血、不自动产生地面血迹。 |
| 数量上限 | 每名员工每夜至多一次流血，合计至多两次；同一事故重放不刷新伤口寿命。 |
| 免费止血 | 柜台每夜两份敷料，实际取用1秒，包扎自己或1.5格内伤者3世界秒；完成才耗一份，取消退回预留。无需抽奖、付费或精细QTE。 |
| 地面血迹 | 仅真实流血期间的实际移动产生，每走2格落一枚，每人最多6枚；每枚30世界秒，自行失效，擦拭1.5秒。伤口出现前的移动和夜班已结束后的请求路程不计入。 |
| 后续怪物 | 同一事故至多一个血源消费者，F26与F32不能重复占用；当前阶段预算和有效伤口余命均至少45秒才开12世界秒预告，并预留物资、合法路线与席位。 |
| F26额外前提 | 必须有同一事故的实际活动血迹，最多绑定3枚；到场再查，若全数已被处理或过期且没有同事故新迹，则安全退去，不能因为伤口尚在而制造不存在的污物任务。 |
| F32额外前提 | 只认登记员工的活动伤口；地面残迹、狼人外观伤痕不算。真实邀请和1秒标记员工边界仍按其本怪规则执行，不获得对所有怪的无敌区。 |
| 结束 | 包扎或90秒自然止血结束伤口；F32最后合法目标消失后3世界秒离场。F26按到场前是否还有真实血迹、已生成的沾染物是否封存处理，不要求为交袋再制造垃圾。 |

### 两个实际分支

**正确预防：**发现玻璃 → 隔离并取工具 → 安全清扫 → 没有割伤回执 → 没有活动血源 → 本次事故不能触发F26/F32。玩家做对了就应少承担一项威胁。

**失误后补救：**实际接触碎片 → 90秒伤口 → 真实移动才落迹 → 导演复核剩余预算并选择一个合法响应 → 玩家取敷料包扎、处理已存在的痕迹 → 本次实例按真实状态收场。预告中先止血或把血迹擦净，不会触发“必须先让怪来才能胜利”。

F21若准备衍生怪，子席位必须引用当前F21父实例。玩家在受伤前停机避险，释放尚未使用的子席位；已经割伤后修好设备，只修设备，不抹去伤口或撤销仍有效的血源处理。

## 3. 来源存在，但时间上不成立的条件

### 3.1 真实店长不能出现在早期变体

真实店长固定在夜班预算700，即游戏05:50回店。旧F20和F48某些变体却要求他陪同，而对应主怪可在预算20、260或620到场，条件不可能按原排程满足。

修正为F20使用E009实际团体订单，考验单份供物与普通团单分盘；F48使用E022实际小票机故障，考验手工编号交付和员工帽权限。这些变体复用当前工作与同一怪物，不额外生一位店长或新的主怪。

E035本身保留在72事件中，只在真实店长已到场且已核验后进入候选。事件最多6秒，最晚预算714开始；余额不足或有关键威胁就不投。普通陌生访客仅留在公共区或改约白天，不成为第三名常驻员工。E031的正常授权查账与同一F20/F48冒名查账分别核验，不能同时要求“真实授权”和“未授权冒名”。

### 3.2 F42的8秒必须量地图

按携物2.4格/秒、空手3格/秒，加上开门1秒、取物1.5秒、放下1.5秒、关门1秒：

| 既定底图往返 | 单程距离 | 最小操作合计 | 能否进8秒窗口 |
| --- | ---: | ---: | --- |
| 后门—垃圾箱 | 10格 | 12.5秒 | 不能 |
| 后门—装卸位 | 8格 | 11秒 | 不能 |
| 验收位—后门外阈值 | 9格 | 11.75秒 | 不能 |
| 后门内候运—门外阈值 | 3格 | 7.25秒 | 静态基准可以，余量0.75秒 |

因此改成**窗口外预先搬到候运位，窗口内完成跨门短转运并返回关门**。最多两批，剩余窗口不足就等下一次。垃圾仍要实际投箱、货物仍要实际上架，跨门回执不等于整项店务完成。遇拥堵、额外携物限制或已有动作占用使局部合计超过8秒时，禁止开始该批次。这些是可复算的静态下界，不是手机手感已通过。

### 3.3 报价可以晚接，工单却不能越过阶段

六类特殊订单同时受“未接受时24世界秒耐心”和“阶段末减去完整执行时长”约束，先到就停止接单。

| 怪物 | 接受后完整预留 | 阶段预算最晚接受点 |
| --- | ---: | ---: |
| F06 | 45秒 | 75 |
| F09 | 70秒 | 50 |
| F27 | 90秒 | 30 |
| F44 | 30秒 | 90 |
| F48 | 30秒 | 90 |
| F51 | 45秒 | 75 |

默认第20秒到场时，F27实际只有到第30秒的接单窗口，不能再等到普通耐心的第44秒。其余数字也要与普通耐心取先到者，并扣除已预留义务。临界时刻的合法动作提交优先于同刻过期一次，重放提交不能生成第二份接受回执。

### 3.4 计时必须有真实起点

- F07的45秒原意就是从实际出现开始，本轮把这一点写成明确字段和检查。提前挂座位牌是准备，重挂或重复出现回调不能重置45秒。
- F49高温变体的“多停一轮”改为：基础合盖累计20世界秒，高温在该次冷却开始时实际生效则额外20秒，共40秒；开盖暂停而不清零，重复开合不叠时间。
- F60失去有效视线目标后的退场统一为3世界秒，清理旧文字的2秒冲突。
- F02补入实际班前或本班工作回执的来源链。班前领物回执可以存在，不能把它说成开班后已经成交的销售。

F25可以使用前班原销售单，但必须经本班真实交接引用。当前历史守卫只检查同班同场景、早于首兆的交接回执；不可变原单真实性、原物件对应和跨班退款唯一性仍需F25适配器，不能把原单的班次号改写后硬过检查。

### 4.1 四个事件不再依赖未定义状态或奖励

**E060噩梦余波：**上一夜实际结算SAN低于40，且当前SAN仍低于40，同一前夜来源只触发一次。选择安静活动按现有A05结算SAN+15，或继续A03学习得到学习点+2、精力−6；均占正常一格，不再叠发事件恢复或另扣SAN，不新增无生产者的“未处理恐惧”。

**E064福利双选：**使用已有普通夜班券一张、15分钟整备；按同一抽取前保底状态生成两件不同合法候选，揭示前存档预留与候选。最终只选一件，保底更新一次。关闭再开不重抽、不退券；没有该品质的合法池就不扣券，也不偷偷降低保底。揭示前拒绝无代价。

**E065奖券碎片：**实际可选工作或F47封袋领取回执产生；同一根来源只结算一次，每夜最多一个来源附加一碎片。3碎片在15分钟整备内换1普通券，可跨夜跨周积累，不占手提格。F47第一份实际兑现可附加1碎片，后两段仍是5、8金币，不能把一个任务拆成三次事件领取。

**E072未用商品退货：**移除没有真实生产链的“意外多付款”。玩家在同一采购窗口内交回实际付费买入、未用且未转移的原物，花5分钟，按该购买行实际支付金额退款一次；抽奖和赠品不能当付费商品退，折扣购买不能按原价套利。保留物品就不返币、不平白加关系。

## 5. 单人步骤正确，双员工和时间边界仍可能出错

已在有限参考实现中复现并修正下列问题：

| 反例 | 修正 |
| --- | --- |
| 两名员工同时处理同一退货，生成两张回执 | 员工操作锁之外增加对象／目标锁；同物只提交一次，不同物仍可并行。 |
| 两人同时封同一份废物，生成两袋 | 同一源物件到封袋是唯一事务，提交、取消、到期都处理锁。 |
| 用已有遭遇编号再接受契约，覆盖活动或已拒绝状态 | 实例ID不可复用，不覆盖活动或终态。 |
| 长步行请求途中失败或到06:00，仍记整段移动并落血迹 | 只累计实际推进的世界时间与实际流血区间；伤口产生前、自然止血后与终局后的路程不产迹。 |
| F21事故未绑定真实父遭遇、席位或工位 | 先有实际激活回执、具体工位、合法阶段与父席位，才可发警报；子席位引用同一父实例。 |
| 擦拭途中血迹自然消失，仍产“清理成功”污物 | 目标失效就释放预留，不伪造完成回执或垃圾。 |
| 夜班结束仍留着未提交退款对象锁 | 交班取消未提交事务并释放预留，不反向取消已经完成的结果。 |

参考模型仍依赖调用方提供真正的移动、碰撞、取物和当前占手事实。它验证了这些有限反例的状态转移，没有实现完整员工AI或物理取物流程。

## 6. 不应误删的可达条件

复核并不把所有低频条件都删除。F10已有N04限制；F19在N02/N05可以使用此前真实交易的两份凭据；F40/F45若此前实际E027送货在首兆前完成，早期阶段仍可有真实树苗／货箱与痕迹。应按实际历史筛选，不能为了省检查把合法玩法一律砍掉，也不能为了保留玩法倒造历史。

来源稀有意味着该条件的怪物少见；没有条件就保留其他合法候选或本阶段工作。到场后才能观察到的形态、伤迹和吞入顺序，也不应错误地要求在首次预兆前已经看到答案。

## 7. 编程规模与验收边界

当前做法保留有限状态、固定物件槽、实际回执和简单定时器。修补优先减少无用状态：普通餐份代替未提供的供物，现有道具代替新保护令牌，现有SAN记录代替恐惧层数，已有付费原物退货代替额外收银差错系统。

没有增加复杂血液模拟、任意裂片物理、无限叠加伤情、自由建筑或60套独立AI。需要真实移动的拿、放、走、关门仍是世界操作；QTE只在许可的局部特写中使用，并检查即将到来的日程标记与关键处理预算。

可复现结果与完整机器输出见[验证文档](09_validation.md)。本轮层次包括：60来源依赖见证及删源负例、跨文件时间与资源检查、四条F42静态路线，以及有限伤情、准入和奖励事务场景。报告保留输入摘要，便于后续内容改动时重新核验。

完整客户端还需验证动态寻路与同时占位、完整60卡适配、低SAN黑视与触控可用性、实际随机权重、经济平衡、跨班凭据持久化，以及多事件组合种子的可解性和趣味性。不得把当前静态PASS描述成这些工作已经完成。
