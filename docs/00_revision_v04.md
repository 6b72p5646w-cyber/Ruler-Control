# V0.4：60只怪物动作规则与完整地图

## 本轮用户明确要求

在既有便利店交互基础上合理泛化，参考《玩具熊的午夜后宫》等游戏的设计方法，完成F01—F60交互规则。手机俯瞰视野下，店内约占五屏，另有店前空地、后门垃圾区，以及玩家家、道具店等地图。把已达成共识同步到本GitHub仓库。

继续保留的用户要求：00—06夜班、一周周期但每天阶段相同；四资源；低SAN缩小QTE判定区并出现黑视；怪物把真实店务变成动作问题，随机事件制造题目变体；员工两人含主角，另有可被假扮的店长；白天学习、休息、采购装备宠物；临时道具、装备、宠物和类似塔防的辅助部署要有用。F12回形针引出、F13生肉入冰柜的核心解法不变。

## 本轮形成的具体设计提案

1. 全60种都有观察线索、真实操作、状态流转、成功判定、失败补救、工作/地图绑定、至少两项事件变体、条件难度与实现层级。
2. 以12类共享机制复用10动作、16工作、8空间组件；怪物差异来自信息、触发、状态和结算，避免开发60套独立小游戏。
3. 店内30×30格，默认竖屏世界视野12×15格，面积比5.0；这是连续地图。五个功能区大小不相同，门外空间额外计算。
4. 同场景有正门前场、后院垃圾区和东侧通道；形成店内环路与店外备用环路。另有三个单屏白天场景和街区行程菜单。
5. 监控采用五路带时间戳快照，设备采用三个固定回路，声音附等价视觉线索；承接参考游戏的信息/维护压力，但与暂停特写、手机操作一致。
6. 路线和调度先检查可达与时间，再检查强度；地图某一门故障不能偷偷令任务必败。

这些条目的具体格数、视野方向、怪物数值和新操作细节是本轮设计提案，尚未由用户逐条审定或通过实机测试。用户认可方向与本轮新增提案分开记录；“完成设计”不等于“60只怪物客户端已实现”。
