# BC02：广告位置、暂停和奖励事务

本轮先把广告作为客户端正式接口设计好。当前没有真实广告 SDK、广告位 ID、账户后台或广告商投放；有限参考使用显式模拟回调。后续 Codex 在完整一夜可玩后接入平台适配层，不能把测试按钮当成线上完成证明。

## 三处入口

| 位置 | 玩家看见什么 | 完成后所得 | 次数与边界 |
|---|---|---|---|
| 主动暂停 | 菜单内独立“广告”卡片/横幅，继续和设置有独立空间；也留插屏适配接口 | 无奖励 | 首次实际游玩60秒后、每逻辑夜最多展示1次；跨夜至少180实际游玩秒。后台暂停不触发，未填充不阻挡继续。插屏默认不开，待平台验收后配置。 |
| 成功夜结 | “观看广告，本局金币翻倍（额外+N）”与普通继续按钮 | 再发一份本夜已结算金币 | 每成功逻辑夜一次；普通金币先入账，失败夜没有此邀请；只翻金币，不翻经验、灵能、券或装备。 |
| 安全抽奖页/成功夜结 | “观看广告，额外获得1张抽奖券” | 普通抽奖券1张 | 每成功逻辑夜一次，下一夜开班前可领；抽样仍耗1券和15准备分钟、使用原概率与保底。 |

一小局指正式的一晚：达到720世界秒并把实际在场威胁处理完、正常顾客安全离店、玩家仍可结算。处理一只怪物不额外制造广告额度。练习、失败或退场不制造成功夜结邀请。无广告照常获得全部基础工资、经营收益、经验与基础券，免费主解也照常可用。

### 第7夜需要特别处理

BC01已有“第7夜旧周金币计入成绩后清空、新周120币”的规则。若这时仍弹金币翻倍，额外金币立刻被清空，广告会徒有收益字样。因此BC02第7夜**不显示金币翻倍广告**，保留有实际价值、跨周保留的额外抽奖机会。没有新增旧周采购窗，也不暗中把旧币搬进新周。

这是在现有七夜经济下明确选择的产品规则。如果以后要让每个第7夜也能翻倍可消费货币，需要单独设计永久货币或修改周结经济，不能由广告 SDK 顺手改变钱包归属。

## 收益究竟如何算

本夜金币 `G = 80工资 + 绩效奖金 + 实际订单金币 + 实际杂活金币 + 实际根奖励金币 + 有额度的存活金币`。正常结算先发 `G`，完整看完这一入口的广告再发 `G`，本夜共 `2G`。初始120、旧余额、商店退款、广告奖励本身均不进入再次计算。

额外抽奖只发普通券，不进行抽样、不改变保底、不指定稀有物、不覆盖已展示结果、不产生E064双选资格。实际抽奖仍由EQ01唯一抽样事务完成。包满进入原领取箱，已领券跨周保留。广告资格来自真实成功夜而不是手机日期；首周基础8券，加七次可选广告最多15券。不能通过失败重试、改时区或反复开抽奖界面增加额度。

金币与额外券入口互不替代、不能一个视频同时领两个奖励。对应的经济验证必须分别比较无广告、只翻金币、只加券、两者全看的升级和永久装备节奏；本轮的回调反例检查不冒充这些未来客户端平衡测试。

## 所有广告暂停都必须冻结同一个世界

暂停服务保存多个持有者：手动菜单、后台、当前广告实例、恢复确认。任一持有者存在就停止世界推进。广告关闭只释放自己的持有者，不能顺手解除玩家手动暂停或后台暂停；回来后仍由玩家点继续。

被暂停的包括怪物移动与攻击、子弹、永久毒及待成熟毒层、水渍/血迹寿命、工作进度、顾客耐心、断电预警、设备支援、回血、存活奖励、夜班截止和随机流。广告加载的5秒超时使用独立墙钟。恢复时丢弃广告期间的墙钟差和旧触摸输入，只推进新的游戏帧，不补跑几百秒战斗，也不额外赠送恢复无敌。

暂停页的广告卡片不覆盖“继续”；窄屏广告区折叠或移至按钮区之外。无填充与离线时正常暂停，继续入口一直有效。插屏是否可用由目标平台实测和配置决定；保留接口不代表立即每次暂停强制播放视频。

## 从观看到入账的事务

1. 先读取成功夜的不可变结算回执，生成固定 `offer_id` 和明示奖励。奖励金额来自结算账，不来自按钮、客户端传入的任意数或广告返回字段。
2. 玩家主动点击后准备新的 `show_nonce`，先把请求、递增sequence和完整状态通过版本检查持久化，拿到提交确认才允许provider.show。未提交nonce不外发；重启从已提交序号续增，不能复用已经展示的请求。加载超时/取消后旧nonce失效，迟到的onLoad不得突然打开广告。同一时刻只能有一个展示请求。
3. 真正进入showing状态后监听同一实例的关闭结果。onLoad、show Promise成功、点击广告和进入后台均不是观看完成。
4. 完成通知、一次性领取键、金币/券增量和版本号在同一个存档事务提交。重复回调/丢ack返回原回执。界面在提交成功后才显示额外收益和允许继续进入下一夜。
5. 提前关、无填充和错误不发额外奖，也不扣普通奖。保留未完成资格，玩家可明确重试。进程中断而没有可靠完成证据时不能凭墙钟推定看完；原资格保留。

结果页关闭命令只作用于当前最新、尚未关闭的成功结果页。旧命令迟到时不能把已经open的下一夜改回pre_shift，旧邀请也不得复活；广告真正show之前再次检查当前阶段。当前视频已关闭时，即使奖励因回执/周归属失效被拒绝，仍须终结该show并释放它自己的暂停，保留手动/后台暂停和恢复确认，不能因为拒奖而永久冻结游戏。

普通金币广告只在原结算结果页和仍开放的原周钱包领取。正在显示的视频由平台关闭按钮退出；尚在加载则可直接取消后继续。未来真实适配器处理同帧关闭、后台恢复、取消和结果页跳转时，必须先提交收到的合法完成事件，再处理下一条界面导航命令，避免把已完成奖励送到新周。

## SDK核对与真实能力边界

腾讯广告官方培训可检索内容说明：关闭回调里的`isEnded`区分完整观看和中途退出。BC02只在当前展示的`isEnded === true`时申请额外奖，未知值不算完成；不兼容“undefined也算看完”的旧捷径。见[腾讯广告官方操作指引](https://training.tencentads.com/uploads/202406/EPLBpxYt_5dDA71.pdf)。检索时PDF直开403，本轮采用官方搜索索引中的对应回调片段，没有据此宣布平台全部最新运营规则。

微信官方类型仓库的[调用示例](https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/test/game.test.ts)包含激励视频的load/show/onError与插屏的onClose。平台适配器须成对注册/注销监听、处理Promise失败并做能力检测。本项目的频控、奖励范围和暂停安排是产品设计决定，不宣称是平台强制数值。

本地`isEnded`只是SDK完成信号，不是服务端密码学证明。正式联机奖账还需绑定账户、检查合法夜结、nonce和幂等领取；若所选广告平台提供服务端完成验证能力，接实际能力，不能发明微信SSV端点。后台流量主资格、appId、adUnitId、真实设备广告回调与平台投放规范都属于发行接入验收。

## 给Codex的模块边界

`AdProvider`只提供能力、预加载、展示、取消、关闭事件；它不能修改玩家血量、金币、券或抽奖结果。`PauseService`负责暂停持有者；`RewardLedger`负责合法邀请与唯一入账；`CampaignRepository`负责整笔存档和版本竞争。先实现标注模拟的FakeProvider及DisabledProvider，再接WeChatProvider，测试构建不能使用真实广告位。

本轮[结构化合同](../content/ad_contracts_bc02.json)、[有限实现](../scripts/bc02_ad_reference.py)和[反例检查](../scripts/check_bc02_ads.py)核验一个实际BC01路线夜结、300秒暂停、旧回调、提前关闭、缺失完成状态、周清和SQLite中断恢复。`RunStore`沿用BC01参考封装来验证同一文件原子性，增加的广告分区只属于参考；正式客户端必须有独立BC02存档版本和显式迁移，不能把参考扩展当作已完成的线上迁移。

复现：`python3 scripts/check_bc02_ads.py`。证据见[报告](bc02_ad_report.json)。真实SDK、联网防改档、微信设备和观看广告后的整周平衡仍按[落地计划](98_bc02_codex_delivery_plan.md)验收。
