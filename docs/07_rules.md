# 20条店规与可达解锁（V0.6）

规则是稳定安全边界。当前条件生命周期以[condition_lifecycle_v06.json](../content/condition_lifecycle_v06.json)为准；60怪具体行为继续查[当前怪物卡](21_monster_gameplay_v05.md)。

## 解锁顺序

保留逐步解锁，但不把第一次受害或付费学习作为基础解法前提。导演先规划候选，提供对应免费规则与操作教学，确认后才允许危险到场；提示描述眼前条件，不自动揭示怪名。白天研究提供更多识别线索和备选策略。

## 三处容易误读的边界

- H14的一次独立对照只验证特定现象；高风险身份权限仍须H04的两类独立来源。旧照片可以证明当时发生过什么，超过当前在场时效后不能证明现在人在哪里。
- H01的暂停新客入店对应窗口模式；窗口不是自动服务或通用无敌。柜台没人时不能凭模式结算订单。
- H19只把队伍门线与安全复店作为必要安全目标，普通店务和销售影响收益。H20使用既有真实店长接班，不生成第三名常驻员工。

## 条件必须有来源与结束方式

事件、怪物与店规都必须说明状态由哪个真实动作、可见事故、已登记初始事实或接受的契约产生；何时到期、如何提前解除、前提消失时怎样取消。未发生的销售、伤情、离岗和承诺不能为了出题临时补写。

预兆发出后仍复查前提。玩家及时处理危险可得到预防结果，不立即补刷一只怪抵消准备；系统原因导致前提失效则无惩罚取消，释放本实例的预留。

## 时间与交班

订单、预兆、到场和小时边界使用阶段预算时钟；移动、伤口、耐心与效果持续时间使用世界模拟时钟。精细特写冻结世界并在退出时支付一次明示预算，开始前不得跨下一个未发日程边界；同刻先派发日程再判断是否可开始。阅读与系统暂停不推进任何时钟。

真实店长在N06第100预算秒按预定流程回店，玩家用两类独立事实核验并准备账单钥匙。真实06:00先结到期契约及已合法提交的成功，再判关键危险，最后交班。06后的专用模式只允许已有记录、预声明柜台核验及交付；核验可产生范围有限的当前观察，不提供新店务、收入、恢复或追加主遭遇。

## 实现边界

这些是设计约束与数据合同，尚不代表完整客户端已经实现。条件生产者、动作提交、到期分支和存档恢复都要接入后，相关内容才可投放。

## H17与H20的当前时序

H17的普通休息需要合法工位；每夜一次的恐慌应急稳定允许随身启动、边走边累计8世界秒。不能把普通休息的工位门槛套在这次补救上。H20在真实06:00先结清已登记到期契约，再检查仍活动的威胁与恐慌；存在任何活动恐慌都不能借交班暂停跳过。只有清关后才进入不推进战斗和资源时钟的身份核验／交接模式。详见[条件合同](../content/condition_lifecycle_v06.json)。
