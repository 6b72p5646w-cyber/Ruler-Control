# SA02：设施的真实营业动作与一次战斗联动

复核基线：`aa7941aef0bfc82f4cef15337084b0a0ad3dbc59`。

**便利店的14类设备已有职责；五个数值候选仍未启用。本次收口把没有真实工序支持的加速撤下，并固定一次联动究竟绑定哪件物、哪次操作、哪张回执。** 这份合同不声称设备已进入可玩客户端。

数据：[facility_contracts_sa02.json](../content/facility_contracts_sa02.json)。它只覆盖 SA01 的 FR01、FR02、FR03、FR04、FR06 候选中动作、回执和付费语义。其他9类职责、免费主解、三个实际电器、塔与陷阱能力及原状态规则均沿现有权威。

## 1. 为什么撤下三种营业加速

FR01 普通结账有当前真实来源：W01 的普通模式已经简化为1.5秒，窗口/静音按原规则为3.5秒。因此可以准确描述候选加速为1.275秒或2.975秒；这只是省0.225秒或0.525秒，不证明它值得消耗1格应急电。

FR02/03 的旧 W05、W07 模板虽然存在补货长按、热食制作，但其普通分支已转到 D02/D03 的简化搬放流程。不能重用历史4秒/6秒模板，也不能任选1.5秒作为新加速基数。FR04 更明确：同件登记肉的取物、搬运、入柜、合盖就是现有冷链/主机制步骤，规则已要求保持原时长；所谓“非关键工作段”尚无具名消费者。

因此，FR02、FR03、FR04 不再声称“营业耗时×0.85”或“省0.225秒”。它们的营业价值就是完成原来必须完成的真实补货、热食交付和冷链工作；可选付电让同一份完成回执附带一次战斗配合。没有新增家务、配料、工作数或收入。

来源：[当前店务与D02/D03](../content/store_systems_v05.json)、[W01/W05/W07普通动作分支](../content/interactions.json)、[必要主机制时长](../content/equipment_contracts_eq01.json)。

## 2. 五个候选现在分别承诺什么

| 设备 | 真实营业动作与价值 | 可选战斗配合 | 数值与状态 |
|---|---|---|---|
| FR01 收银台 | 原普通订单结账；仅该真实动作耗时×0.85，同组加速取最强且最低0.8 | 原订单结账完成后，对合法投影范围内最近1个已显形敌对独立血池加1咒 | 1电；20秒完成机会；30秒再用；咒10秒 |
| FR02 货架 | D02原货箱真实上架，库存守恒；不缩短取放和路程 | 推进同一实际货架上1座合格单弹塔正在进行的装填工作，幅度为该次完整装填工作的10% | 1电；20秒机会；30秒再用；截到ready且无溢出 |
| FR03 热食台 | D03已有热食真正放到登记交付槽；保留原动作、食品与订单 | 在自身合法投影域内对最近最多2池各加2热 | 1电；20秒机会；30秒再用；热6秒；达到共享阈值才烧伤 |
| FR04 主冰柜 | D03同一登记肉真正入有效柜并完成原合盖；F13若同时成立仍按其原机制结算 | 主规则先结束，再向合法投影域内仍在场的最近最多2池各加1寒意 | 1电；20秒机会；30秒再用；寒6秒；不直接承诺冻结 |
| FR06 核验台 | 免费身份核验继续；并列已有证据不制造新身份事实 | 在真实台位对同一已显形合法敌人持续扫描2秒，完成后给予3秒易感 | 起手仅预留1电；成功才扣；成功时起30秒冷却；3格真实LOS |

五者始终为 `enabled=false`、`runtime_integrated=false`，并非新购买入口。FR01/03/04 的敌方圆形作用仍需至少1.5格名义半径及合法遮挡补偿；FR06用3格实际射线范围。**塔投影通过12/12静态检查不能代替设施自身发射点和作用域验证。** 消费者或本设施几何尚未登记时，激活直接拒绝且不收费。

30秒冷却只表示再次使用的最短间隔。D02/D03的工单与子步骤仍按原计划有限产生，欠单续做、取消重做、反复放物或开关柜都不新增回执名额。不能用“每30秒触发一次”估算收益，更不能为了达到这种频率增加新工单。

## 3. 一次工作联动必须绑定原动作

每次预约保存活动ID及下列不可变身份：

- campaign、week、逻辑夜、attempt；
- 设施实例、原工单、原action；
- 同一实际物件；结账时为原订单/交易所绑定的实际对象。

预约只在原动作首次起手的同一次确认中扣1电，不额外增加启动秒数。FR02在真实最终上架动作、FR03在原热食交付动作、FR04在原冷链最终入柜/关盖动作起手时绑定。不会在长途搬运开始时先扣费，等待超过20秒后才抵达设备。

FR01的0.85只快照到这一原结账action。其他三个候选不写速度修正。不同工单、不同action、换物件、换设施、换attempt的完成回执均不能兑现原预约。已经完成的工作也不能事后付电追领联动。

### 取消和续做

原消费者若取消后重新创建action，旧机会立即结束，已付电不退。普通结账遇取消/营业方式改变需要重新开始，因此FR01旧加速与联动不能转到新结账action。

FR02/03/04只有在原工作执行器本身允许保留**同一个action和同一物件的真实进度**时，才可将预约暂挂并续做；它们不会发明新的保留进度能力。续做不扣第二份电、不更新原截止、不转工单。若原执行器只支持重新起手，则按取消处理。

### 20秒边界

只允许已经开始的绑定动作在 `实际完成时刻≤起手时刻+20秒` 时兑现。恰好20秒时，先提交真正已经完成的原动作及主规则，再清理过期机会；超出哪怕很小的一段时间都不触发。不能在第20秒才开始或续做新动作。

这条是“已开始工作完成与预约截止同刻”的顺序，不能用来延长敌人状态。热/寒/咒/易感仍各自采用 TD05 的原截止和清理顺序。

## 4. 完成回执、战斗目标与失败

顺序固定为：原店务提交 → 同动作的真实主机制终态 → 清除已离场/死亡目标 → 设施选择仍合法接收者 → 一次设施衍生效果。

同一关柜动作可以同时提交原D03冷链和真实F13完成事实，但不会因此重复发工作奖励或制造第二张主机制回执。F13已经离场时不能再获得该次寒意；同域其他仍合法敌人可以接受原定效果。

一次真实完成会消费这次机会，即使没有合格敌人或正在装填的塔。不会退款、稍后补发、储存待用攻击或重复开关柜领取效果。假回执、读取UI、重复播报、已处理回执与设施自身衍生效果都不能充当新的工作完成。

敌方目标按真实距离排序，等距按非空稳定血池ID；只选择合法、已显形、实际相交且层/LOS合格的敌对独立血池。合法非敌对响应角色也不接受这些对怪效果。同血池多部件只算一次。货架则从同一设施上的合格单弹装填白名单中，选择剩余装填工作最多的一座，等值按非空稳定塔实例ID。已ready、多弹仓、多波、纸偶、场周期、封印储印、毒成熟、电过载均不属于这次装填推进。

源断电/隔离使尚未触发的预约永久结束；重新供电不能重开原预约、退电或重置冷却。已经合法附着的状态仍走自身原截止，不因台体断电提前删掉，也不能反复通电续时。冷链基础主解与可选应急电仍相互独立。

## 5. 核验扫描的付费点

FR06起手仅预留1格电；预留期间这1格不可被另一个动作花掉。没有完成前不扣库存、不启动30秒冷却。

同一台位有尚未完成的扫描预留时，拒绝第二次扫描或付费工作预约。不能用两个不同活动ID同时起手，等第一次成功后让第二次绕过刚开始的冷却。

扫描必须在原台位真实完成2秒并重新核对同一目标、当前attempt、源、范围、LOS、层和动作合法性。成功时一次原子提交“扣1电＋给3秒易感＋下次允许时刻=当前时刻+30秒”。中途移开、取消、源失效、失去LOS或目标离场/不再合法，释放预留，不扣电、不进入冷却。已成功后目标再离开不退款。

它始终不能创造身份事实、找到隐藏本体或将普通来客变成敌人。命名中的“显影”只对应已经可选敌人的短易感候选。

## 6. 与装备、塔、状态的事件边界

设施的热、寒、咒、易感和装填推进均标为 `facility_secondary`，携带原action与回执身份。这些衍生效果不伪造玩家使用、塔发射、工作完成、主机制完成或真实移动事件，不继续递归触发EQ01反应装备。

同一真实主动作本来能够合法触发多个不同监听者时，各监听者仍按原卡一次处理；设施去重不会吞掉另一个装备真实应得的原触发。例如同一原动作同时满足冷链工作和主机制，它的合法两种事实仍由原消费者提交，设施不能自己补写第三种事实。

设施实际附加的状态仍正常进入TD05阈值、免疫、到期、结局和聚合规则。加2热不直接烧伤，加1寒不直接冻结，易感不叠成-2阈值。装填推进只作用于已经存在的装填时钟，截到ready无溢出；之后真实发生且通过瞄准/目标检查的那次塔射击仍是正常主攻击。正常正数电伤与其电荷反馈完全保留TD05规则，不引入全局电荷上限或电荷连锁次数上限。

## 7. 仍需要实作与平衡的部分

这次把无来源加速和事务歧义收紧了，尚未提供真实设施发射器、扫描体积、D02/D03世界回调、全夜联合排程或生产存档。

战斗收益也仍需用实跑验证。热食一次2热在6秒后过期，而设施30秒才能再用，单靠该设施无法攒满8热；它是配合其他热源的候选。冰柜1寒的8%减速使3.3格/秒普通追逐降到3.036，仍略快于玩家3.0基础步行；不能把它写成保证安全逃跑。收银省0.225秒是否值得花1/12的起始电量，也不能只凭算术判定。

货架一次10%装填推进同样可能很小：完整装填工作为2.2秒时，只推进0.22秒，且目标必须当时正在装填。实际是否多打出一发取决于后续瞄准、目标、控制和遭遇时长，不能只根据推进比例认定它强或弱。

下一步验证应记录真实一夜中设备帮助多完成的订单、形成的安全操作窗口和状态联动次数，并与快照/照明消耗比较。免费主解仍需在0应急电、无抽奖装备下成立。
