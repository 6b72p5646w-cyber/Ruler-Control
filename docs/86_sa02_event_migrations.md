# SA02：旧事件进入七夜模式的明确边界

审查固定基线：`aa7941aef0bfc82f4cef15337084b0a0ad3dbc59`。

## 结论与范围

SA01 已补好主要钱包、夜键、检查点与周清规则，但不能把旧 `enabled_current=true` 直接解释为七夜模式可用。本补件为旧72事件建立逐ID迁移索引，其中**24项经济、库存或宠物交界进行了定向复核，另48项本轮没有重新审完整流程**。所有运行门禁继续关闭；没有声称72事件已接入或都能同场完成。

七夜模式先读取 [event_migrations_sa02.json](../content/event_migrations_sa02.json) 的禁投、分支覆盖和未知拒绝，再读取原事件的真实物件、位置、动作和时钟。`legacy_practice_v010` 保留自己的原合同，本补件不修改旧事件文件。

## 本次发现的跨版本问题

### 1. 原物回收可以绕过个人资产不能兑换周币

旧 E066:B2 允许同一原物按原报价20%回收。例如参考价60、实付42的原物，对应8币。个人物品在EQ01跨周保留，而EQ01又明确禁止出售个人物品换周币。若保留旧回收入口，便可把旧周购买或免费取得的个人资产换到新周钱包。

本次确定：**七夜 E066 只保留B1同ID存放，B2付费回收关闭**。存放没有货币收益，不能删原物再发一份，也不能超仓库容量。E072同周、同采购窗的实付原物退款是另一个有原票约束的事务，不因此改成通用出售。

来源：[原E066及E072](../content/event_contracts_v010.json)、[EQ01个人资产与退款](../content/equipment_contracts_eq01.json)。8币只是旧合同的可复算报价，不表示旧客户端已经执行该回收。

### 2. 借贷没有接入新周账与工资

旧 E071 是借20、到下一绝对夜还25，并与E045核账、工资抵扣相连。SA01的工资扣款参数只表达最多20币的店务债，不能用它代替25币借贷。借贷本金、义务、到期、抵扣预留和回滚没有在七夜模式完成独立映射。第7夜还额外存在本金本周清空、旧债义务继续跨周的问题。

本次确定：**E071和E045在七夜所有夜次暂不投放**，不是仅屏蔽第7夜。既有旧模式借贷存档不能被无声清债、当成咖啡债或硬塞进店务扣款；没有专门迁移前拒绝转换，保留原存档。这里没有新建借贷或资金系统。

来源：[原E045/E071](../content/event_contracts_v010.json)、[SA01生命周期](../content/run_lifecycle_sa01.json)、[有限工资模型](../scripts/sa01_lifecycle_reference.py)。

### 3. 夜间特卖、赠礼与宠物备用不能重填开门清单

E040旧支路允许营业中花42币取得I21，与七夜个人采购时段不一致，因此七夜暂不投放。E067仍保留核验真实礼盒的玩法，但新增I21先形成**本夜待固化的固定领取权**；只有真实安全交班后才可在既有合法窗口领取。它不进入当前开门清单，不改变I21只作用F50/F60的白名单，失败随本夜检查点回滚。

E069找回已经被宠物藏起的同一原物可以保留。其B2“取一件自有备用”必须限制为**原ID已在本夜清单、尚未消费且实际存在的备用**；仓库里未携入的另一件不能在营业中补进来。必要任务物、钥匙、免费保底餐、预留急救物和已承诺原物依旧不能被藏。

来源：[原E040/E067/E069](../content/event_contracts_v010.json)、[EQ01清单与采购窗口](../content/equipment_contracts_eq01.json)。

## 唯一账本与保存条件

- 原行动回执是唯一经济来源。E054只是同一A09的30币入口，不在原行动和事件层各发一次。E038的6币、E042的4币仍须真实完成并各按原事件唯一回执结算，不冒充订单或怪物根。
- 拒绝旧周、旧夜或旧尝试命令；未知商品、来源、价格、宠物、欠款和奖励种类不自动补默认值。请求者不能随便给出`coin_delta`。
- 夜内币与新领取权仍属于SA01整夜检查点；失败要同时回滚收益、物件、效果、来源回执和使用额度。原先已固化的个人物品保持原所有权。
- E072只回退同周同采购窗、未使用未转移的原支付行；发票价42就退42，不按现价60退款。彩票、赠品、跨周原票和已回收物均不适用。未决开奖期间不能用退款改变其持有快照。
- 第7夜个人固定领取权可跨周保留；旧周货币不随领取权一起转换成新周钱。领取仍不能倒流进已经开班的物品清单。
