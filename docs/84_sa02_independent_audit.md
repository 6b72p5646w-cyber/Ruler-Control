# SA02：独立复核、设备效果收口与剩余设计

> 历史快照：本文件保留当时的审计和候选。2026-11-20 的新营业/随机入侵/成长及首发 P0 设计以 [BC01 总览](88_bc01_revision.md)、[P0 验收](93_bc01_p0_acceptance.md)和[当前权威表](../content/system_authority_bc01.json)为准；SA02旧事件/已验证响应的未覆盖规则继续继承。

审查日期：2026-11-20。固定基线：`aa7941aef0bfc82f4cef15337084b0a0ad3dbc59`（SA01）。

## 1. 结论

**还不能认定完整游戏的所有机制均已自洽。** 当前已经建立主要玩法合同，并有大量结构检查和有限反例；本轮在这些检查全部通过的基线上，仍找到真实工序、旧事件迁移和非敌对机制响应的跨系统缺口。它们说明检查的覆盖范围有限，不能用通过数量替代完整夜班的可达性和可玩性证明。

**便利店设备已经有设计，但完整的营业增益与塔防协同系统尚未实现。** SA01整理了14类职责和5个优先数值候选。基础设备已有订单、库存、原物、信息、通路、恢复、塔挂点或电器节点职责；所有新增候选仍未启用。最明显的缺口是部分候选写了加速，却没有与当前真实工序对应。

本轮以[SA02唯一权威](../content/system_authority_sa02.json)为拟实现模式入口，补三组限定修订：

1. [设备动作与效果合同](85_sa02_facility_contracts.md)：只对有真实来源的工序谈加速，并绑定原工作与原回执。
2. [旧事件七夜迁移](86_sa02_event_migrations.md)：明确个人资产、夜间清单、当周钱包与旧交易的边界。
3. [机制离场响应合同](87_sa02_rule_response.md)：明确合法非敌对响应与持续伤害、压制的优先级。

这些是设计合同与有限参考模型修订。新增运行功能为0；没有据此开启105个AI、设备候选或随机事件。原两怪练习继续使用原模式；本轮没有把它当作新模式完整试玩。

## 3. 本轮独立发现及处理

### 3.1 冷柜加速找不到真实受益工序

D03当前只明确热食交付、登记生肉入柜和关柜，目标时间包含行走；F13与之共用同一登记肉箱。EQ01又明确主机制取物、搬运、存入、封存与等待不受普通工作加速。FR04的“非关键工作段×0.85”因此没有一个已登记、可引用的受益动作。不能拿D03整段26秒直接打折，也不能用假定1.5秒的算术示例当成工序存在的证据。

FR02和FR03也存在当前简化动作与旧长按/QTE模板之间的映射缺口。为避免增加没有玩法价值的杂务，本轮撤下FR02/03/04未映射的15%工作加速及假定省时数，保留真实上架、热食交付、冷链关盖完成后的有限战斗协同。只有收银有明确普通1.5秒、窗口/静音3.5秒结账来源，保留其速度候选。必要主机制时长不变。

来源：[D02/D03](../content/store_systems_v05.json)、[原候选](../content/facility_roles_sa01.json)、[必要动作边界](../content/equipment_contracts_eq01.json)。修订详见[设备合同](85_sa02_facility_contracts.md)。

### 3.2 一次付款必须绑定一次真实工作

原候选同时写了“起手加速”“20秒内下一份回执”和“取消不退款”，却没有充分区分已消费的速度资格与尚未触发的战斗资格。若工作A获得加速后取消，再改做B，可能出现同一电量加速多个保留进度的工作，或B先完成却误领A的战斗协同。

本轮将设施实例、逻辑夜、attempt、工作、动作与原物身份绑定；不能换单继承、回放UI领两次、用空开关柜造工单。真实工作和主机制先提交，再判断当前战斗目标。精确到期、取消、续做、断电、无目标和扫描提交各有明确结果。缺真实动作或几何适配时，不进入付费预约。

这是原未启用候选的设计歧义，不是已上线刷取漏洞。有限模型验证事务边界，不替代实际工作处理器与物理投影。

### 3.4 永久毒与反复压制可能阻塞机制离场

S40要求怪物真实取走纸本，含2.5秒取纸响应；原规则离场类显体压制后4.5秒恢复25%HP，永久毒量保留。按原有限生命模型，S40的HP200、灵防0.6、毒量q=125时，恢复为50HP，两次1秒毒伤各25即可再次压制，活动窗只有2秒。

**确定的事实是该数值循环成立；“一定死锁”取决于尚未定义的响应取消方式。** 若实现把每次压制解释为取消并重开2.5秒取纸，就会一直无法取件。原合同没有排除这种实现，所以尚未闭合。q=125是合同允许的状态，本轮没有证明玩家在真实地图中必然取得它。

只加“塔停火”不足以解决已经附着的永久毒。本轮为明确登记、已满足真实前置条件的`rule_leave`非敌对响应片段定义受限优先级：真实取物/移动继续完成；停止该根的敌对攻击与新的受击压制；永久毒量和原物进度保留；原世界时钟和状态截止继续；不补算期间未结的伤害。不能把界面按钮当成主机制完成，也不能获得玩家全局免伤。

该机制只对列明的响应片段成立，不适用于机制解锁击杀、机制削弱、普通人或未登记动作。失败/超时不得回血、退物、重置预算或重复进入刷保护。实际到达与物件提交后才可结束根遭遇、发一次原奖励。各怪仍需要自己的片段适配与真实路线证明。

来源：[S40原卡](../content/monster_scp_b_md01.json)、[原生命模型](../scripts/md01_reference.py)、[共享终态](../content/monster_contracts_md01.json)。修订及适用范围见[响应合同](87_sa02_rule_response.md)。

## 4. 除塔和陷阱外，设备应该怎样发挥作用

设施的营业价值包括真实交易、库存处理、信息、通行和资源恢复；防御价值包括状态协同、改善走位、控制怪物依赖条件及帮助完成原机制。无需让每台设备同时提供攻击和工作加速。以下明确区分基础职责与候选强化。

| 设备 | 已有营业职责 | 已有或拟议的防御/怪物影响 | 当前边界 |
|---|---|---|---|
| 收银台 | 原订单结账、权限交接 | 柜台遮挡与对应员工边界；候选完成同一结账后给1咒 | 结账×0.85和附咒仍未启用；本体不免费获得积毒塔 |
| 货架 | 真实库存、搬运、上架、文具供给 | 形成绕行与遮挡；候选同一上架完成推进本架合格塔10%装填 | 不加速未映射工序；不是所有塔都接受装填推进 |
| 热食台 | 已登记热食交付、热饮/灶位操作 | 真实电器节点；候选完成热食给最多2个合法池各2热 | 本体不持续灼烧；不凭空增加制作工序或配料 |
| 主冰柜 | 冷链、F13同件肉箱封存 | 免费原主解、真实电器节点；候选同件关盖回执给最多2池各1寒 | 撤下无受益工序的加速；空开关不触发 |
| 饮料冷柜 | 取真实库存饮品、按登记资格备用 | 电网中继，已有饮品支持体力等资源 | 不免费产饮品，不新增第二电器或减速光环 |
| 核验台 | 并列事实、物件与权限 | 原伪装机制；候选2秒扫描使一个合法显形目标易感3秒 | 扫描不识破隐藏身份；成功提交才扣费与冷却 |
| 监控 | 快照和既有记录 | 最后已知位置、路线及等待信息 | 信息有时间和视域边界，不是持续凝视或穿墙锁定 |
| 照明 | 看清真实工位和路线 | 只影响已定义依赖照明的怪物节点 | 需要真实照区与逐怪白名单，不是通用破隐 |
| 迎宾/广播 | 声道、叫号、纸号交付 | 开关对应声音依赖；已购广播塔另走原控制 | 静音不能把已在场怪物删除，也不免费复制T06 |
| 门窗/帘 | 接客、窗口服务、交接与通路 | 按实体和怪物合同阻挡特定视线、射线或入口 | 店内怪不因关门离场；门加固仍无已启用消费者 |
| 水槽/支阀 | 清扫真实湿格、处理支路 | 擦断/关闭特定水怪所依赖的真实连接 | 不产生全怪减速，也不是无条件总开关 |
| 验收/分袋/隔离工位 | 同件物验收、归属、数量和封存 | 为对应撤权、封存、离场或削弱提供真实操作 | 不生成无限槽或通用封怪能力 |
| 员工补给区 | 已有食品、咖啡、短休与携入清单 | 沿原资源改善跑动、生存与恢复 | 不凭空产物、不免伤；债务与占手继续成立 |
| 抽奖机 | 固定时段以券和准备时间领取真实奖励 | 通过装备与道具改变后续构筑 | 营业不开；机身不攻击、不挂塔、不算AP，准确落位尚待完成 |

来源：[14类职责与物件绑定](../content/facility_roles_sa01.json)、[本轮限定覆盖](85_sa02_facility_contracts.md)。目前真正参与电网的AP仍只有热食台、主冰柜、饮料冷柜三台；同一设备的多个操作面不能重复计数。

### 数值候选还需要证明“值得用”

收银普通结账仅节约0.225秒，窗口/静音节约0.525秒；花掉1格初始12格应急电是否合算，主要取决于战斗收益和信息工具的机会成本。热食一次2热、层持续6秒而设备冷却30秒，单靠自己达不到8热点燃门槛；一层寒的8%减速使3.3速度的普通追逐怪变为3.036，仍略快于玩家3.0基础步行。它们应被标为协同效果，不能宣传成独立击退或必定脱险。

这些算术不证明候选无用。应在真实一夜里验证它能否帮助完成一次点燃/冻结、多做一单、少受一次攻击，或换到必要的搬运时间。未得到这样的证据之前，不应继续给设备堆更多小百分比。

## 5. 仍缺的设计，按阻塞程度排序

| 优先级 | 缺项 | 需要形成的具体交付与完成标准 |
|---|---|---|
| P0 | **统一地图与物件落位** | 抽奖机、仪式石、SCP任务模块、设施作用面、塔投影、陷阱、顾客队列在同一张地图落位；明确体型、层、占手与必留路线。零体力、无特定装备仍能到达免费主解 |
| P0 | **完整夜班工作/追逐排程** | 给出连续六阶段脚本，包含预兆、真实订单、工作、追逐、主解、响应/退场和交班；验证实际时间，不能预先输入“完成8单”就算成功。明确停火/选目标的实际操作 |
| P0 | **组合准入与资源争用** | 对首版开放怪物逐组审朝向、视线、双手、共享原物、湿路、门、射线和主解窗口；至少证明一条可执行处理顺序。仅“最多两套危险序列”不够 |
| P0 | **全状态保存与恢复** | 将设备预约、响应进度、旧事件待领取权、原物身份、计时器、RNG与周账映射到真实存档。验证同刻提交、后台中断、半写入、重试、跨夜和周清 |
| P0 | **真实时间驱动的整周经济** | 把实际营业完成率、塔陷阱、装备、应急电、补给与维护放进同一周账；比较低营业、常规、重陷阱、重装备与设备协同路线。原24币预留只作预算，不另扣税 |
| P1 | **设备完整产品规则** | 确定首版是否需要独立升级树；需要时才写价格、容量、安装、故障、维修、退款和周清。现阶段没有全店HP，不能设计“万能修满” |
| P1 | **第一周教学与触控** | 分夜教工作与免费拒绝、布防、状态、读前摇、投石、缠绕与领奖；首次危险前可免费演练。手机能完成保持朝向、搬物、投石和挣脱 |
| P1 | **失败复盘与可读性** | 显示实际死因、最后一次危险、未完成主解与可改路线；区分目标不可选、缺电、工序不合格、范围不达。重试说明与真实回滚一致 |
| P1 | **第7夜动机与后续周目标** | 已有“收入先入账后周清”，但最后一夜经营成绩的价值仍需定义并展示；后续周要有主题、组合变化和知识进展，不能只加HP/移速 |
| P2 | **扩池与表现** | 在已证明的一夜/七夜上扩更多怪物、地图、叙事和外观；再做声音、动画、真机性能和发行质量，不以数量替代闭环 |

这部分延续并细化[SA01缺项](82_sa01_missing_design.md)。本轮修订解决局部合同歧义，无法替代这些时空、经济和操作设计。

## 7. 下一步最值得做的工作

优先完成**一个完整夜班的空间与时序设计包**：使用已有内容，选覆盖三种结局与主要交互的代表怪物，把真实物件、路线、订单、设备协同、主解和交班放进同一连续记录。每项都要给动作时间、可选失败补救和零付费主解。

完成设计包后接入并验证这一夜，再延展到七夜与新组合。此时测试的问题应是“玩家在这一时间、这一位置、这些物件和威胁下能做什么”，而不只是“每张卡单独是否写了一个解法”。
