# V0.3 验证记录

日期：2026-11-17。

## 内容与配置

60个志怪候选、72项事件、20条店规、24项即时道具、24件装备、8只宠物和18组联动继续保留。V0.3新增10个共享动作、16项店务、3类QTE、8个空间/状态组件、2份追逐蓝图、12项事件工作变体及8个部署套件。

检查覆盖：编号唯一、来源引用、工作/原语/事件/怪物链接、固定日夜阶段、时间预算、抽奖概率与保底、宠物共用次数、设施资源不刷新、状态与物件标签一致，以及内部文档链接。F12/F13的旧胜利机制及相关交叉联动已替换；民俗原型事实与引用继续保留。

## 规则逻辑

`prototype/check_rule_core.mjs`覆盖20个场景，包括：

- 低SAN可见缩区、0.6秒命中下限、连续SAN分档及黑视安全半径。
- 身体朝向、固定遮挡与距离边界；危险有反应缓冲。
- 追逐/即将受击/空间不合规时不能开特写，开始后取消也付成本且只付一次。
- F12默认追人、只认合法回形针点、锁定目标、停食、消耗、到期、被引出店外后锁定终态。
- P04能在正在停食时追加一次1秒，不重复加成。
- F13先找本次任务肉，触肉蓄势后追人，放下肉不消除怒态。
- 抢先入柜成功、同帧触肉/断电不能推翻已经提交的成功、跨遭遇旧凭证不被复用。
- 错误、不可用或太远的冰柜不吞物品；解除后开柜/断电不复活。
- 首次受击有明确轻伤、SAN损耗及跨怪物共享的短暂无碰撞保护。

这些场景使用提供的位置、可达性和碰撞事实，验证的是纯逻辑。没有把它们称为寻路仿真或可玩测试。

## 复现

在仓库根目录运行：

```sh
python3 scripts/validate_content.py
node prototype/check_rule_core.mjs
```

Python检查只用标准库，JavaScript检查使用Node内置模块，无第三方依赖。成功时输出`PASS`，失败时非零退出并指出问题。两个命令不联网、不写设计内容，也不操作GitHub。
