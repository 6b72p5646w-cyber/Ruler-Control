# 复用机制、条件联动与实现范围

> V0.5迁移：本页保留V0.4历史细节与组件推导，当前玩法以[门店机制](20_store_gameplay_v05.md)和[60怪派生](21_monster_gameplay_v05.md)为准。F12/F13精确蓝图继续有效；本页自然语言状态条件不是客户端运行配置。

## 从参考作品得到的设计方向

玩家的压力应来自“我现在该观察哪里、维护什么、能否完成手里的店务”。怪物用不同信号、触发条件和成功判定改变这组决策。反复答文本题无法支撑全部60种内容；60套独立玩法程序也不适合首个微信版本。

因此，60张卡使用同一套10动作、16工作、8空间组件，再组合12类机制模块。新内容的独特性通常只需要一项额外状态、一个有限序列或一条对象标签规则。复杂度标记是共享底座完成后的相对工作量，不是按“填配置即零成本”估算工期。

| 机制 | 复用内容 | 可形成的不同操作 |
|---|---|---|
| MC01 线索与快照 | 时间戳、来源ID、声源图标、固定画面层 | 核对出现顺序、判断远近、区分旧画面与新异常 |
| MC02 朝向距离遮挡 | 视锥、格距、静态遮挡、宽限计时 | 侧身结账、保持距离、借遮帘断开直视 |
| MC03 区域与连通 | 干湿、冷热、安静区等离散标签图 | 清掉水路连接点、维持热食区、分段过水 |
| MC04 物件与容器 | 登记ID、占手、所有权、交付凭证 | 搬肉入柜、归还皮衣、隔离未知货物 |
| MC05 订单与账本 | 扫码、称量、实测、库存和现金差额 | 狐精容量复核、零钱封存、反向足迹盘点 |
| MC06 有限顺序 | 最多3步的对象次序和进度 | 解绳、打包、取回吞入的物品、按指令交材料 |
| MC07 时间与维护 | 世界计时、预警、失败缓冲、阶段升级 | 循环巡检、短暂屏息、节拍停步、限时唤醒 |
| MC08 目标与追逐 | 标签优先级、固定导航、诱饵、攻击窗口 | 引出、拦截目标物、携带后被追逐 |
| MC09 身份与权限 | 真实实体、声称身份、知识和授权分离 | 比对工作记录、限制通道、双证据解除权限封锁 |
| MC10 固定位置 | 槽位、标记、座位、施工区和装置 | 留空位、摆路标、清出交接区、预先布置 |
| MC11 合约与托管 | 上限、期限、物件托管和可见账单 | 限额交易、储水交换、讲述与收据逐项对账 |
| MC12 设备回路 | 固定开关、运行/故障/待修、局部供电 | 分区断电、保持冷链、恢复照明、关闭声源 |

## 三种时钟不能混用

1. **世界时钟**：移动、声音窗、追逐、设备维护、诱饵寿命和快照年龄。系统暂停、阅读面板和安全特写均冻结。
2. **局部操作时钟**：特写QTE开始后只推进本次操作；SAN缩区在尝试开始时快照。按钮/拖柄尺寸不缩小，判定区域和显示区域一致。
3. **阶段工作预算**：120秒。世界实际运行和已经提交的特写成本各扣一次；退出已开始的特写仍扣该次成本。读取说明不扣，不能暂停后获得生产、回复体力或免费设备维修。

需要真实时间窗口的怪物必须在世界视图完成动作，不能要求在完全暂停的画面里等待怪物走来。监控新快照的采集是1秒世界动作，存在风险；采集后看旧图可暂停。快照标记世界时间和年龄，8秒以上显示“旧图”，不会自动刷新。第一版做5个区域的角色位置/设备状态图层快照，不做5个实时摄像机。

## 设备管理的范围

门店有前场照明、冷链热食、后场监控三个固定回路，状态使用枚举与简单负载。正常营业不强迫玩家始终盯着电量条；只有明确设备事件或怪物修饰引入过载/停电压力。设备自身电池和次数继续遵守部署系统，个人仍只有精力、SAN、饱腹、体力四项资源。

玩家可以选择局部断电、切换应急灯、修好断路器或转移货物。断掉冷链不能悄悄使已完成的F13胜利失效；危险计时和修复所需来回距离在事件入场前检查。不能一边冻结世界看维修特写，一边让冰柜在后台腐败。

## 调度先保证可解，再制造压力

一个遭遇申请的是一组条件：工作站、特殊物件、通路、时间窗、主动追逐名额和操作修饰。调度器按以下顺序准入：

1. 相关功能已实现且启用；基本规则已告知；初见必须有安全预告。
2. 绑定当前阶段可做的真实工作，检查事件允许时段。不能把白天随机事件当夜间瞬时障碍；白天事件只提供已经记录的准备状态。
3. 必需道具/容器存在且可达，不能要求抽奖或宠物；身份事件必须绑定已入场的实体。
4. 从当前格计算必要路径，加实体动作、承诺特写成本、现有订单和一次补救。总预算不超过剩余120秒；可选订单先被减掉，关键店务不能凭“拒绝怪物”自动完成。
5. 检查排他资源和空间限制，再计算总强度。每个工作最多两个额外空间/操作修饰，低SAN产生的手感影响也计入负担。
6. 按一周的既定上限投放：通常每小时一个新主遭遇，重大事件替换该位置；首周同时假扮者最多一名，主动追杀玩家最多一只。

在达到并发上限或预算不足时，取消的是未生成的候选，不突然删除玩家正在处理的怪物。残留债务、保留座位等若跨阶段，必须作为可见义务继续占资源/强度预算，不得把实体退场当无限免费叠加的理由。

准入压力为基础值1—3加复杂度附加0—1，再计兼容的条件增减。F38与F54的合计初始负担为4，不能仅按旧字段3点塞入低预算阶段。F35的75秒合约期限使用阶段工作预算，包含特写已承诺成本；F22离场劳动、F36占位时长等实际等待使用世界时钟，暂停期间不生产或累计等待。

## 条件联动示例

| 组合 | 使它更难的具体条件 | 可用回应与硬门槛 |
|---|---|---|
| F01狐精＋F16图尤尔 | 同时核商品重量和封存零钱，两个不同账本被争用 | 真同事处理已验普通客，玩家先封零钱再称量；无足够空闲工位/窗口则不准入 |
| F05河童＋暴雨 | 原先不连通的湿格接成路径 | 先擦一个关键连接格，比盲目全店拖地更快；始终留干燥通路 |
| F05河童＋F57塔尼瓦 | 一个要断水路，一个要保留指定水路 | 仅独立排水沟和营业湿格可隔离时允许；同一必需水道同时开/关属于硬矛盾，禁止 |
| F28诺肯＋F57塔尼瓦 | 关闭声源水点可能打断水路 | 两者使用不同已登记水域才可同场；禁止用含糊“更高难度”掩盖相反要求 |
| F12＋F13 | 两个主动追逐都争夺携带、绕行和注意力 | 首个可玩版本明确禁配；不会靠增加移速强行凑难度 |
| F13＋冷柜报警 | 终点失效，需要备用容器 | 未实现备用冰柜时禁配；实现后先登记可用备用点，并重算路径；成功凭证提交后不复活 |
| F21报丧预告＋F22委托 | 同一个真同事被两个位置/时间要求占用 | 预先调班或顺序完成；若两条窗口重叠且同事是唯一必需执行者则禁配 |
| F29配餐＋热浪 | 黄油层次与食物保温窗口变化 | 已告知温度表和可用配餐台，做短序列后及时交付；不模拟融化流体 |
| F42哨声＋门铃故障 | 失去一条辅助距离提示 | 保留独立强弱图标及门影；不能同时删除全部近远证据 |
| F47伊阿拉＋F58雾笛残留 | 多个声音进度使交接时机容易混淆 | 两个声源独立图标/进度，不随机改输入；无强制移动 |
| F49火蛇＋F58热食区 | 清除垃圾余火同时保留合规热食热源 | 两类热源用不同标签，不写成“必须全灭火”的矛盾规则 |
| 倒垃圾＋后门锁卡 | 备用外环单程36.67秒 | 优先现场开锁，或减少本小时压力；不能再叠90秒紧急怪物任务 |

这些是可审核的条件提案，尚不是已经接入客户端的调度代码。旧18项联动例子继续提供母题；本轮新增的每怪变体提供更细的工作、事件和地图关系。

## 首个可玩版本与后续内容

全60张设计卡在本轮完成，制作按共享系统分批：先地图灰盒与16店务，接F12/F13，再加入F01计量、F05湿格、F07留座、F16现金、F22离场委托、F29配餐、F38工作记录和F60转身遮挡，形成10种机制的纵向样片。样片不是完整60怪发行版。

之后做设备与声源、固定路标和合同系统，再把剩余角色依赖这些底座接入。F14附身等较高实现复杂度内容可保留完整规格，但默认不投放。每一批都要在实际五屏地图中检查路线、黑视、单手/双手操作、暂停恢复、后台切换和低端手机表现，再开放功能门槛。
