# BC01：营业、战斗和免费主解共用地图的 P0 装配

> 版本导航：本文保留 BC01 当时的设计和有限参考证据。当前明确修订以 [BC02 总览](94_bc02_closure.md) 和 [BC02 权威表](../content/system_authority_bc02.json) 为准；客户端实施从 [Codex 开工入口](100_bc02_codex_start.md) 开始。旧短时设施规则不与 BC02 并行叠加。

## 结论和证据边界

BC01 在既有 `MAP_STORE` 实体地图上补上顾客公共服务面、普通杂活站点、首批特殊任务模块和安全落位规则。角色路线使用真实四邻接地格、墙体、柜架、门和 0.3 格身体半径；不能用两站之间的直线距离代替走路。

`content/map_composition_bc01.json` 是本次装配合同，`scripts/bc01_map_reference.py` 提供可执行导航、遭遇脚本和组合门禁；`docs/bc01_map_report.json` 保存实际测量结果。运行 `python3 scripts/check_bc01_map.py` 可复现验证。

这里完成的是 **P0 的具体地图设计、有限参考准入与反例验证**。它不把 105 张怪物设计卡当成 105 个已经运行的 AI：105 条都有准入结果；12 条纳入实际地图与动作脚本参考，其中 11 条可进入导演参考的危险事件池，S38 只用于无挑衅、无奖的被动异常反例；其余 93 条保持关闭，并逐条记录缺失操作位或尚未验证的物件/行为条件。所有正式客户端准入位仍为 `false`。

## 2. 杂活必须按真实走路排班

下面的时间使用基准空手 3 格/秒、重物 2.4 格/秒、任务肉 2.6 格/秒。它们是**只有走路的时间**，拿取、清理、卸货、收银等动作还要另外加。

| 路线 | 纯走路时间 |
|---|---:|
| 柜台 → 仓架 → 商品架 → 柜台 | 27.25 秒 |
| 柜台 → 卡车 → 验收 → 仓架 → 柜台 | 38.33 秒 |
| 柜台 → 工具柜 → 冷区水渍 → 封袋 → 柜台 | 28.67 秒 |
| 柜台 → 工具柜 → 货架镜面水膜 → 封袋 → 柜台 | 42.00 秒 |
| 柜台 → 工具柜 → 血污 → 封袋 → 柜台 | 43.33 秒 |
| 柜台 → 工具柜 → 垃圾 → 封袋 → 柜台 | 39.33 秒 |
| 柜台 → 电闸 → 柜台 | 20.00 秒 |
| 封袋位 → 后院垃圾箱，重物速度 | 6.67 秒 |
| 任务肉原箱 → 主冰柜，任务携带速度 | 7.69 秒 |

因此旧 D01–D06 的若干“包括路程的固定目标秒数”不能再证明新循环可行。例如清血一趟仅走路就超过旧清洁工作 28 秒目标。BC01 导演必须消费当前角色位置和实际路径，安全窗口不够就保留已完成步骤，余下任务转下一个营业/恢复窗口；也可在玩家实际带着工具时连续清理，不能每项都虚构一次自动往返。

普通补货、收银、卸货、清洁、复电维护只在 `BUSINESS` / `RECOVERY` 推进。怪物入侵时同样名为“搬肉”“擦湿边”的动作，若是该怪物原物件主解，仍属于战斗目标；不能把普通维护积压变成战斗期间的额外罚单，也不能用做杂活的回执冒充主规则回执。

从街道到冷冻货、结账再离店，顾客仅走路约 34.17 秒；从最远公共商品位撤到街道约需 13.33 秒。预警至少要给得出这段实际清场时间，若顾客尚未走出就延期激活，不能倒计时一到把人删除、自动结单或者让其进入塔的敌对列表。

## 4. 实际火力区与“做完主解”之间的区别

F01、F05、F12、F13、F60、S09、S29 都需要后续合法伤害。有限参考选用原 TA07 挂点 `[7.5,24.5]` 的 T02，朝北真实发射口 `[7.5,23.999]`。目标路径为：

`[7.5,22.5] → [10.5,22.5] → [10.5,21.5] → [7.5,21.5] → 起点`。

四段均在真实地面上，无固体截断射线；离挂点最远 4.243 格，低于 T02 L1 实际 5.5 格射程。主角引导点为 `[10.5,22.5]`，完成主解后走到这里也要计时。`combat_reference(monster_id)` 每次重新检查当前地图上的身体、路径、射线、距离和支持高度；在 `[7,23]` 添加实际路障会得到 `legal=false`，不能继续结算“假装命中”的伤害。

同一怪物也必须从自身记录的位置实际走到 `combat_target`，按主解后的速度计时，集成层需要这段实际到达回执。不能把主角移动完成误当成后仓怪物已经瞬移到塔前。F13 主解后保持 `low_air`：参考采用沿无障碍走廊登记的低空路径投影，既不穿墙，也不因此触发仅对地面生效的夹子。

这里提供的是给战斗结算器使用的合法火力条件。它没有声称怪物 AI 会无偿站在圈里，也没有证明主角可以站桩无伤。实际 T02 每发、毒 tick、怪物 HP 与终态结算由整夜参考继续计算；没有合法伤害的弱化/解锁根必须保持未终结，不能等待一个预设秒数就发怪物奖励。

## 5. 随机临时陷阱的实际落位

顾客使用货架蓄存的临时陷阱遵从设施合同：先固定 R01 / R02 / R07 模板，再验证此模板的真实占格，不能因为地形不合适就重抽更有利类型。

地图提供 10 个候选起格，店内和门外各 5 个。它们避开已验证的顾客路径、免费主解路径、操作站位、S29 亮区等保护位置。R01 的 `1×2` 需要逐格检查，并分别尝试 0°/90°；当前地图得到 16 个可用旋转落位。R02 / R07 为 `1×1`，当前 10 个起格可用。

最终落位还要用此刻真实角色位置、占用格、已锁定主解路径重新验证。以下任何一项都会拒绝落位并保留顾客额度：

- 已有 8 件付费/临时合计陷阱，或该模板放下后超过 16 个合计地格。
- 已经存在一件临时陷阱。
- 所选模板的任一格被付费物件、规则原物、角色或已保护路线占用。
- 两格 R01 只剩一格容量，或没有真实连续可用的两个格。

临时物仍是敌对目标专用且不阻挡人物/顾客的陷阱。不能卖出、回收退款、变成背包库存、补弹或为付费陷阱重置寿命；战斗结束只移除临时实例。

## 6. 组合准入先保证能完成

BC01 把活跃根上限设为 2、主动追玩家的敌人上限设为 1、压力总额上限设为 2。压力 ≥2 的遭遇，以及 F12、F13、S09、S29、S40、S43 这些需要独占明确操作窗口的首发案例，全部独占入侵。不能仅因为数学上压力够小就任意拼两张卡。

当前只有两个明确条件上下文可同时通过：

| 组合 | 所有条件同时成立时才允许 |
|---|---|
| F17 + S34 | 两份原物和两组槽位独立；F17 在前场领取区，S34 爆音只在打包台区域；先完成 F17，再进入 S34 区域；实际仍只有一个追逐者 |
| F17 + 无挑衅 S38 | S38 没有被触碰、攻击，也不在塔选敌列表；只作被动无奖封存；不是第二个敌对追逐者 |

任一来源、原物、区域边界、被动状态或预约条件丢失即拒绝。其他组合一律拒绝，包含未装配怪物之间的组合。测试对 105 条的 5,460 个无序组合都执行了这层门禁；这个数字是**准入判定覆盖量**，不表示已经试玩了 5,460 场双怪战斗。

怪物造成的停电是绑定真实遭遇根的状态事件，可伴随一个已准入单根，不能凭空算成第二只怪、第二份掉落或者自动延长加成。清场后复电杂活再进入安全工作队列。

## 7. 验证发现并修正的具体不一致

本次不是只验证 JSON 存在。实际几何排查发现并处理了以下问题：

1. **F05 水阀角色名不能代表擦水站位。** 一般水阀位到割点超过 1.5 格，现脚本显式走到干侧再擦。
2. **F17 的 4 格后退不能塞进 1 秒。** 现按路径和主角实际移动速度计算，领取的 2 秒是怪物动作，不被主角交互熟练度缩短。
3. **F12 固定出生点离收银位不足 5 格。** 导演不能默认柜台就是所有怪物的安全出生距离；参考可先实际走到 `safe_counter=[7.5,27.5]`，距 F12 出生点为 5.099 格，或改选当前合法候选。不能瞬移玩家或强行贴脸生成。
4. **停电与免费主解可达性分离。** 正常电器效果停用，但断电不创造锁门、锁冰柜或收费照明条件。
5. **S40 / S43 的高毒量响应使用实际地图路径。** S40 从后门外到取纸位实际 4 格，再完成 2.5 秒原件领取；S43 从验收位到退场边界实际 12 格，完成真实退出后还要手动门闩。q=125 的反例状态不会把同根反复压制成无法交付，也不因此复制奖励。
6. **F17 也会被永久毒卡住取件，不能遗漏。** 最大 HP 230 的 F17 从压制恢复到 57.5 HP；q=125、灵防 30% 时每秒毒伤 43.75，再次压制只需 2 秒，但实际 3 格走近加 2 秒领取共需 2.909 秒。BC01 因而只把 F17 的已开三结、原包裹已在槽、玩家已退 2.5 格外的取件段加入响应白名单。`ParcelResponseReference` 保留当前 HP、永久毒、已付成熟与绝对到期，现有控制不清空；实际减速仍影响走路，99% 异常减速输入也按既有 60% 全局上限处理。保护预算按原路径最低合法速度和原 2 秒领取一次绑定，不能刷新截止。丢失原物或退距条件立即退出保护，其他敌人照常能攻击玩家。

运行报告同时保留全部路线距离、首批脚本动作/行走/真实等待分项、临时陷阱候选、旧塔投影不受影响的距离依据、组合门禁结果和失败反例。其用途是把 P0 设计落实为可审查、可复现的约束；正式 AI、移动战斗胜率、更多体型和未装配后续怪物仍必须在真正接入后另做验收。

## 8. 给集成层的接口

    footprint=(1, 2), object_count=7, footprint_count=14,
    occupied=[], protected=[], active_actors=["cashier"], temporary_active=False,
