## 实现要求

- 新建`client/`，采用TypeScript纯领域核、Canvas2D表现层和Web/微信平台接口，保持旧两怪练习可回归。先完成C00/C01，共享接口稳定后可并行做环境与顾客模块。
- 从权威JSON编译出具名动作/条件处理器，中文文案不执行；未知处理器给出具体阻塞，不用默认true通过。
- 一个GameClock驱动所有世界行为。暂停/后台/广告冻结怪物、毒、血迹、工作、回血和计酬；广告关闭只释放自身暂停，用户点继续后从新delta开始。
- 一个ObjectRegistry维护真实原物和身份；移动必须走真实路径，取放须实际距离/占手/许可。原物搬走、源过期、电源变化会使未提交动作或瞬移失效。
- 正常顾客完成真实使用与付款才有支援；12种来源各2份。不得直接在开战时随机给buff。FR06使用公共核验面，FR11先喝完同杯再回收，包裹/叫号流程保留各自真实回执。
- 持续支援按实际RAID结束解绑；回血由实际HP owner应用后`hp_regen_ack`扣真实恢复预算，断电不补发，原物与预算随存档同时保存。旧BC01 JointNight不识别这个新事件，不能原样拿来当新联合运行器。
- 主解按逐怪免费原物和真实前提实现。F05缺湿路不入场；水/镜/影端点用来源版本复验；F13低空不触地面陷阱；F17保留高q下真实领取响应。不能用参考`make_combat_resolver`或“脚本结束”制造实际击败。
- 不变更未被BC02覆盖的毒、电、HP/SAN、根奖励、周清规则。不要为了优化悄悄加衰减、硬上限或重置源物。
- 不在RAID推进补货/卡车/普通清洁，不用杂活债逼玩家边追逐边经营。本根擦水/封血等战术操作有不同身份和反馈。
- 本轮M1先把三个广告槽和provider接口留好，真实广告在C10接；开发用Disabled/FakeProvider且明确标注模拟。没有广告正常继续。金币翻倍和抽奖券的唯一领奖必须经CampaignRepository，广告代码不能直接修改钱包。

## 你交付M1时应能现场演示

1. 一名顾客真实进门、取同件库存商品、付款和离店，产生真实支援储备；随后补货或清洁实际完成得奖。
2. 预兆时已在场顾客沿路线撤离，货箱原地暂放；免费原物和怪物线索可见。
3. F12、F13、F05、F17能各自单独练习，也能进入随机完整夜班；玩家会真实受伤、失败、取消操作和恢复，正确主解能真正离场/削弱后击败。
4. 一场180秒的受控长战斗仍有整场支援；断电关掉电器buff和过载，恢复后不补发治疗。陷阱保留到触发或场末。
5. 暂停300秒后回到同一位置、血量、原物和动作进度；不会突然补跑攻击。正常结算给一次实际收入，重试不重抽、不保留本夜失败收益。
