## 2. 本轮设计决定

升级采用L1→L2→L3二选一，再开放两条可独立购买到II的强化线，共6塔族、12分支、24线、48档。两线可同时拥有，有限金币与灵能决定先后。每线I为12币+3灵能，II追加18币+5灵能；两线全满追加60币+16灵能。白天换型保留同价槽位的已付等级，同时禁用旧分支，不退灵能、不刷新冷却。

攻击差异同时涉及首击、短窗口、持续锁定、过量伤害、射线形状、独立血池覆盖和离开射界后的尾伤。低频重击需要可靠落点；高频热印需要同目标连续命中；灵毒抑制真实回复；冷炮创造驻留窗口；灯改变阴影路线或积累曝光；纸偶交换接触位置；广播放大已经建立的阵地与真实规则成果。

T03到L3的金币投入调整为100，而非旧草案135，使范围塔在早期单目标阶段仍有合理保底。它的多目标收益必须来自实际命中的独立血池，不从同一怪的多个身体模型重复获得。

群体接口预留2个根遭遇槽、最多6个额外子体、全场8个敌方actor，每根最多3个子体同时在场、累计最多6个新子体。全部是待实测的上限。共池部件、依附召唤、独立制造和真分裂分别处理；分裂不复制剩余血量、DOT预算、叠层或奖励，也不能清掉已经完成的主要规则事实。

## 3. 交叉审查后修正的反例

| 原问题 | 最终处理 |
|---|---|
| 长钉既有穿甲、射程和穿线，持续单体还压过速贴 | 调整为26/1.8秒、25个百分点自身穿甲；回程对旧目标II仅25%，使低甲长战与高甲短窗分工成立 |
| 购买冻结会清掉寒意，反而损害同塔脆冰技能 | 读取消费前快照；冻结/抗控期间的冷痕能满足脆冰资格，但不储下轮冻结 |
| 纸偶侧击另加1秒冷却，10%攻速使它隔次丢附伤 | 按真实正常近战周期触发，不再叠加额外1秒限制 |
| 强毒伤来源没有抑复技能，会挤掉弱毒的抑复 | 毒伤取强与回复抑制取强分别归并仍有效的剂量 |
| 混级热印先拆成小剂量取强，丢失已经付费的贡献 | 8枚贡献先合成唯一灼烧剂量，再参与灼烧族取强 |
| 第8枚热印与“下一次命中”有歧义 | 本次先加层后检测；达到8枚即可引爆，满层冷却中不刷新旧层 |
| 定帧只监听准备开始瞬间，会错过中途达到最高曝光 | 最高档且目标仍处于可中断准备期时即可申请快门 |
| 群体按根ID去重会漏打眷属，按模型去重会多打巨怪 | 伤害/状态按生命池，空间按actor，奖励与遭遇槽按根ID |
| 分裂先于本批伤害会吞掉致死伤害，或给子体复制收益 | 整批命中先结清，非致死才分裂，余量守恒，根奖励只结一次 |
| 升级/换型可补满纸偶或复活死亡单位 | 保持全队耐久比例、死亡与重组状态；改变数量需全队存活且离战3秒 |
| 低空被当成地面，炮弹或冻结自动迫降 | 地面炮只打地面；真实迫降必须由明确原型动作或R03提供 |
| 火、灯、纸偶被隐式当成任务火灾、身份核验或血源 | 战斗状态不制造真实环境证据；所有规则成功仍要求原物与实际动作 |

## 4. 已完成的检查及算术结果

复现方式：在仓库根目录执行下列命令，仅需Python标准库。

```sh
python3 scripts/check_td02_design.py
```

本轮18项静态检查通过：版本边界、6/12结构及分支关联、24/48技能结构、同价槽与成本汇总、60个唯一怪物ID、F14关闭、适配引用、地面炮与冻结高度、有限群体总数、热印共享预算、次伤不递归，以及下述特定数值反例。输出保存输入数据的SHA-256，便于确认所检查的版本。

以下是连续合法锁定、没有漏弹、没有其他塔或规则破甲、所选技能全满的稳态算术；长钉回程命中原目标，不计空场蓄能首发，目标灵性防御为0。**它不是完整战斗模拟，也不代表平均实际击退速度。**

| 目标物理减伤 | 穿签长钉稳态单体DPS | 热压速贴稳态单体DPS | 说明 |
|---|---|---|---|
| 0% | 18.06 | 20.50 | 低甲持续锁定体现速贴优势 |
| 30% | 17.15 | 15.25 | 明确的自身穿甲开始体现长钉价值 |
| 75% | 9.03 | 7.38 | 高频物理爆发仍受护甲约束，没有免费真伤 |

这些对照只排除已发现的明显支配关系。短窗首发、转角、子弹飞行、重选目标、真实射线、灵性防御和其他塔的破甲会改变结果，必须在灰盒中继续比较。

其余算术：热罐与长钉的基础单目标DPS/到L3金币之比约0.824；轮班纸偶在真实夹击条件下，0%、10%、25%、30%攻速对应9、9.9、11.25、11.7基础物理DPS；四枚I级加四枚II级热印提供2.5点/秒灼烧贡献。命名攻速档的热印总收益也通过单调性检查，但不代表任意未来攻速档都已验证。

三个独立审查方向分别覆盖共享战斗逻辑、塔族差异与付费收益、既有怪物适配。结果为所交付设计的交叉核对；不等同于六十套AI、控制系统或手机端已经执行通过。

## 5. 灰盒实现与验收顺序

1. **先实现最小战斗合同。** 分离actor、生命池和根遭遇；加入合法目标/高度/射线、统一攻击周期、一次性回执、有限状态截止与主要规则事实。用简单形状显示命中区、预告、剩余层数和防御变化。
2. **优先对比T01A/B与T03A/B。** 对同一条路线分别测试稳定单体、短暂显形、两目标交汇、有限独立子体与共池部件；记录1/2/4秒有效伤害、漏弹、过量伤害、实际覆盖池数及金币效率。
3. **接入代表性辅助作用。** 加T02A、T04A、T05A与R01/R02/R03/R04/R07/R12；使用F03/F05/F12/F13/F40/F50。镜穿和有限子体使用无原型测试体，验证接口时不增加正式怪卡。
4. **同时验证两种胜利路径。** 合法基础配置在不提交主要规则时仍有可伤窗口；正确应对能显著降低追逐压力、打开射界或缩短击退时间。不能用总无敌逼玩家猜唯一解，也不能让满树塔把所有能力永久封死。
5. **通过后补齐剩余分支与内容。** 执行37号文档的并发、控制、分裂与换型反例，再进入七夜经济、手机操作与性能调校。正式美术在玩法反馈和空间可读性通过后开展。

本轮没有验证：运行器集成、真实寻路/命中/遮挡、控制与分裂的并发执行、手机输入与性能、60个完整可玩AI、七夜经济和趣味平衡。旧版22组检查的成绩不作为上述门槛的通过证据。
